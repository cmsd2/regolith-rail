Scenario: **Two trains**. A mine, a factory and a dome, with two trains sharing the line.

## What happens

Both trains see the same low stock at the same station and both respond. One station
gets two deliveries in quick succession and fills up; the other waits for a train that
has already spent its cargo.

## Why

Each train decides from what it can see at its own stop. Nothing tells it that the
other train is already carrying enough for the shortage. In inventory terms, the
policy looks at *stock on hand* instead of *inventory position*: stock plus what is
already on the way.

## What helps

Reserve cargo for the station it is meant for, and count reservations when judging
shortages. [ops.lookahead](/docs/ops/lookahead) records reservations in memory, and
every target block works from the inventory position, so a shortage another train has
covered no longer looks like a shortage.

```lua runnable scenario=two-trains fix
return ops.policy {
  classify = ops.roles.manual { Mine = "supply", Factory = "demand", Dome = "demand" },
  target = { supply = ops.drain {}, demand = ops.fill {} },
  plan = ops.lookahead {},
}
```

Custom code can use the same figure with
[ops.inventory_position](/docs/ops/inventory-position).
