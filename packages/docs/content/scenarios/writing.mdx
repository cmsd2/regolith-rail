A scenario script is a short Lua program that returns a scenario. It calls
*constructs*, functions that take a table of named parameters, fill in
defaults and convert units, and builds the same [scenario document](/docs/scenario-format)
you could write as JSON. Open the **Scenario** tab in the workbench to edit
one; errors appear on the line that caused them.

Scripts use the same [language and sandbox](/docs/language) as policies, with two
differences: there is no `ctx`, and there is no randomness. Anything random in a
scenario, such as demand or storms, belongs in its demand and event processes, so
that every seed can replay it.

## A line in game terms

The [Mars pack](/docs/scenarios/mars) describes a rail line the way the game does:
stations of a size, buildings next to them, and trains.

```lua runnable script
return mars.line {
  id = "outpost",
  title = "Outpost",
  duration = sols(5),
  stations = {
    mars.small_station {
      id = "Mine",
      stock = { Metals = 10 },
      buildings = { mars.extractor { resource = "Metals", rate = 30 } },
    },
    mars.large_station {
      id = "Dome",
      stock = { Metals = 20 },
      buildings = {
        mars.consumer { resource = "Metals", rate = 20, variability = 15 },
      },
    },
  },
  distances = 40000,
  trains = { mars.train { id = "T1", start = "Mine" } },
}
```

Every starter scenario in the workbench is written this way. Open one and look at
its script.

## Units

Quantities are given in units and converted to milli-units, so `rate = 30` means 30
units a sol. Durations are milliseconds, written with helpers: `minutes(5)`,
`hours(1.5)`, `sols(3)`, `days(2)` and `weeks(1)`. A sol and a day are both 24 game
hours.

Values must be exact. A capacity of `0.0005` units fails, because quantities have a
resolution of 0.001 units, and `minutes(1 / 7)` fails because it is not a whole
number of milliseconds. The error names the nearest values that would work.

## Core constructs

The [core constructs](/docs/scenarios/core) cover every part of the format. This
script builds a shop that orders beer from an outside supplier and a truck that
brings malt from a depot:

```lua runnable script
local depot = station {
  id = "Depot",
  resources = { Malt = { capacity = "unlimited", initial = 200 } },
}

local shop = station {
  id = "Shop",
  resources = { "Beer", "Malt" },
  consumers = {
    consumer {
      resource = "Beer",
      poisson = poisson { per_sol = 12 },
      unmet = "backorder",
    },
  },
  converters = {
    converter { inputs = { Malt = 2 }, outputs = { Beer = 1 }, rate = 10 },
  },
  suppliers = {
    supplier {
      resource = "Beer",
      lead_time = discrete { { days(1), 3 }, { days(2), 1 } },
    },
  },
  review = review { period = days(1), offset = minutes(1) },
}

return scenario {
  id = "brewpub",
  title = "Brewpub",
  information = "local",
  duration = sols(14),
  stations = { depot, shop },
  arcs = { arc { from = "Depot", to = "Shop", distance = 600 } },
  vehicles = {
    vehicle {
      id = "Truck",
      route = shuttle { stops = { depot, shop } },
      speed = 5,
      capacity = 20,
    },
  },
}
```

Resources default to every resource a station stores, in the order stations first
store them. A route's stops can be station ids or the station tables themselves.

## Building with loops and functions

A script is ordinary Lua, so repeated parts come from loops and functions. Keyed
tables are visited in sorted key order, so a script builds the same scenario every
time.

```lua runnable script
local stations = {}
for i, stock in ipairs({ 5, 10, 15 }) do
  stations[i] = station {
    id = "Stop" .. i,
    resources = { Water = { initial = stock } },
  }
end

local l = line { stations = stations, distances = { 300, 500 } }

return scenario {
  id = "water-line",
  duration = sols(2),
  parts = { l },
  vehicles = {
    vehicle {
      id = "Tanker",
      route = loop { stops = { "Stop1", "Stop2", "Stop3" } },
      speed = 4,
      capacity = 10,
    },
  },
  arcs = { arc { from = "Stop3", to = "Stop1", distance = 800 } },
}
```

Constructs return plain tables in document units, and a script may change them
before returning the scenario. Use `units()` for quantities when you do:

```lua
local l = line { stations = stations, distances = 300 }
l.stations[2].resources[1].capacity = units(45)
```

## Classic templates

The [classic templates](/docs/scenarios/classic) return a whole scenario for a
well-known operations research problem. Picking one in the workbench writes a
one-line script and a form for its parameters:

```lua runnable script
return classic.serial_chain { stages = 3, lead_time = days(3) }
```

Each template comes with a reference policy, loaded when you pick it, and a page
explaining the problem: the [newsvendor](/docs/book/newsvendor),
[reorder](/docs/book/order-quantities), [serial chain](/docs/classic/serial-chain) and
[fixed-route delivery](/docs/classic/fixed-route-delivery).

## Errors

Mistakes are reported at the line that made them:

- a syntax error or a feature outside the language subset, at its line;
- a wrong parameter, naming the construct and parameter, such as
  `store: capacity must not be negative`;
- a problem found when the evaluated document is validated, at the line of the
  construct that built that part, with its path, such as a route stop that names a
  station no construct defines.

Scripts also have limits: an instruction budget, as policies do, and a largest
scenario of 500 stations, 2,000 arcs, 200 vehicles, 200 events and 100 resources.

## Scripts and JSON

The **Script** and **JSON** buttons convert between the two. Converting JSON gives
an equivalent script built from core constructs; converting a script gives its
document. **Show evaluated document** displays the document a script produces
without changing it. Share links and saved scenarios keep scripts as scripts.
